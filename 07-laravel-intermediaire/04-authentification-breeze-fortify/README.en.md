## 📖 Theory

### What you've already built by hand

In [module 02.5](../../02-php-intermediaire/05-sessions-cookies-authentification-maison/README.en.md) and the [level 02 mini-project](../../02-php-intermediaire/projet-mini-02-gestion-taches-crud-pdo/README.en.md), you built: password hashing (`password_hash`/`password_verify`), session management (`$_SESSION`), CSRF protection, an `exigerConnexion()` middleware. **Breeze automates this entire system**, with a complete interface (registration, login, forgot password, email verification).

### Installing Laravel Breeze

```bash
composer require laravel/breeze --dev
php artisan breeze:install blade    # generates the views with Blade (or "react"/"vue"/"api" depending on the need)
npm install && npm run build
php artisan migrate
```

Breeze generates:
- Authentication routes (`routes/auth.php`): registration, login, logout, forgot password, email verification.
- Controllers (`app/Http/Controllers/Auth/`) implementing all this logic.
- Ready-to-use Blade views (login/registration forms styled with Tailwind).
- A `users` migration already present by default in Laravel (`name`, `email`, `password`).

> 📌 Compare `app/Http/Controllers/Auth/AuthenticatedSessionController.php`, generated by Breeze, with your `Auth.php` from the [level 02 mini-project](../../02-php-intermediaire/projet-mini-02-gestion-taches-crud-pdo/README.en.md): you'll find `password_verify`, `session()->regenerate()` (the equivalent of `session_regenerate_id(true)`, against session fixation) — the same principles, in code generated and tested by the Laravel community rather than hand-written.

### The default `User` model

```php
// app/Models/User.php
class User extends Authenticatable
{
    protected $fillable = ['name', 'email', 'password'];

    protected $hidden = ['password', 'remember_token']; // never serialized to JSON (module 09)

    protected function casts(): array
    {
        return [
            'email_verified_at' => 'datetime',
            'password' => 'hashed', // AUTOMATICALLY hashes on assignment, no more need for manual Hash::make()
        ];
    }
}
```

> 💡 `'password' => 'hashed'` (Laravel 10+) applies `password_hash()` automatically as soon as you assign `$user->password = 'plain text'` — you **never** have to call `Hash::make()` yourself in that case, reducing the risk of forgetting to hash a password.

### Protecting routes

```php
// routes/web.php
Route::middleware('auth')->group(function () {
    Route::resource('taches', TacheController::class);
    Route::get('/profil', [ProfileController::class, 'edit'])->name('profile.edit');
});
```

> 📌 `middleware('auth')` is the direct automation of `Auth::exigerConnexion()` — a single keyword replaces the manual check `if (!isset($_SESSION['utilisateur_id'])) { header('Location: connexion.php'); exit; }` repeated at the top of every protected page.

### Accessing the logged-in user

```php
// In a controller
$request->user();
auth()->user();

// In a Blade view
{{ auth()->user()->name }}

@auth
    <p>Logged in as {{ auth()->user()->name }}</p>
@else
    <a href="{{ route('login') }}">Log in</a>
@endauth
```

### Breeze vs Fortify: when to choose what?

| | Breeze | Fortify |
|---|---|---|
| Views included | Yes (Blade, React, Vue) | No — **headless**, you build your own views |
| Typical use case | Getting started quickly with a complete UI | An existing/custom UI, or a fully custom SPA |
| Customization | Directly edit the generated code | Configure via `config/fortify.php`, without imposing a view |

> 📌 For this training and most projects building a UI from scratch, **Breeze is the recommended choice**: customizing the generated code is simple, and you keep full control since the code belongs to you after generation (unlike a package that would remain a black box).

## ✅ Key takeaways

- Breeze generates a complete, battle-tested authentication system, automating everything you built by hand at level 02.
- `'password' => 'hashed'` replaces the manual call to `password_hash()`.
- `middleware('auth')` protects a route in one declaration, replacing a repeated manual check.
- Breeze provides ready-made views; Fortify is headless, for a fully custom UI.
