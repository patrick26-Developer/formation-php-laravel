# 00.4 — Méthodologie d'apprentissage

> **Statut :** ✅ Disponible

## 🎯 Objectifs

- Adopter une méthode de travail efficace pour progresser sans se décourager.
- Savoir comment utiliser les exercices, solutions et projets de cette formation.
- Éviter le piège du "tutorial hell" (suivre des tutoriels sans jamais coder par soi-même).

## 📋 Prérequis

[00.3 — Git & GitHub essentiels](../03-git-github-essentiels/README.md)

## ⏱️ Durée estimée

15 minutes.

## 📖 Théorie : comment apprend-on réellement à coder ?

Lire un cours ne suffit jamais à retenir une compétence de programmation. La compétence se construit par **la pratique répétée et la lutte productive** : essayer, se tromper, chercher l'erreur, réussir. Cette formation est conçue autour de ce principe :

- Chaque module de cours est **volontairement court** en théorie pure.
- Chaque module est suivi d'un fichier `EXERCICES.md` que vous devez **faire vous-même avant de regarder la solution**.
- Les mini-projets et grands projets appliquent plusieurs modules d'un coup, en situation réaliste.

## 💡 La méthode recommandée, module par module

1. **Lire** le `README.md` du module en entier une première fois, sans exécuter de code.
2. **Retaper** les exemples de code vous-même (ne jamais copier-coller) dans votre éditeur, et les exécuter.
3. **Faire les exercices** de `EXERCICES.md` dans l'ordre, sans regarder `solutions/`.
4. **Comparer** votre solution à celle fournie seulement après avoir produit la vôtre (même imparfaite).
5. **Committer** votre travail avec Git (voir [00.3](../03-git-github-essentiels/README.md)) pour garder une trace de votre progression.

## 💡 Comment aborder un mini-projet ou un grand projet

Les projets suivent toujours le même schéma de lecture :

1. Lire le `README.md` du projet pour comprendre l'objectif.
2. Lire `INSTALLATION.md` et mettre en place le projet sur votre machine.
3. **Avant** de regarder le code fourni : essayer de construire vous-même une première version à partir des modules de cours déjà vus.
4. Consulter `JOURNAL.md` pour voir comment le projet a été construit étape par étape, et comparer avec votre propre démarche.
5. Utiliser `EXECUTION.md` pour lancer, tester, et itérer sur le projet.

## 💡 Éviter le "tutorial hell"

Le piège le plus commun en auto-formation : enchaîner les tutoriels en comprenant chaque étape sur le moment, mais être incapable de reproduire seul un projet similaire ensuite. Trois règles pour l'éviter dans ce parcours :

- **Ne jamais copier-coller** le code des exemples ou des corrigés : retapez-le.
- **Fermer le corrigé** avant d'essayer un exercice, même si vous pensez ne pas savoir le faire.
- **Reconstruire un mini-projet de mémoire**, quelques jours après l'avoir terminé, sans regarder le sien.

## ✅ Points clés à retenir

- Théorie courte → pratique immédiate → confrontation à la solution, dans cet ordre.
- On ne copie-colle jamais le code fourni : on le retape et on le comprend.
- Un projet se lit dans l'ordre : `README` → `INSTALLATION` → tentative personnelle → `JOURNAL` → `EXECUTION`.
- Committer régulièrement avec Git donne une trace concrète de votre progression.
