# 00.4 — Learning Methodology

> **Status:** ✅ Available

## 🎯 Objectives

- Adopt an effective work method to progress without getting discouraged.
- Know how to use the exercises, solutions, and projects in this training.
- Avoid the "tutorial hell" trap (following tutorials without ever coding on your own).

## 📋 Prerequisites

[00.3 — Git & GitHub Essentials](../03-git-github-essentiels/README.en.md)

## ⏱️ Estimated duration

15 minutes.

## 📖 Theory: how do you actually learn to code?

Reading a lesson is never enough to retain a programming skill. Skill is built through **repeated practice and productive struggle**: trying, getting it wrong, hunting down the error, succeeding. This training is designed around that principle:

- Every lesson module is **deliberately short** on pure theory.
- Every module is followed by an `EXERCICES.md` file that you must **do yourself before looking at the solution**.
- Mini-projects and large projects apply several modules at once, in a realistic setting.

## 💡 The recommended method, module by module

1. **Read** the module's `README.md` in full, once, without running any code.
2. **Retype** the code examples yourself (never copy-paste) in your editor, and run them.
3. **Do the exercises** in `EXERCICES.md` in order, without looking at `solutions/`.
4. **Compare** your solution to the provided one only after producing your own (even an imperfect one).
5. **Commit** your work with Git (see [00.3](../03-git-github-essentiels/README.en.md)) to keep a record of your progress.

## 💡 How to approach a mini-project or a large project

Projects always follow the same reading pattern:

1. Read the project's `README.md` to understand the goal.
2. Read `INSTALLATION.md` and set up the project on your machine.
3. **Before** looking at the provided code: try to build a first version yourself from the lesson modules you've already covered.
4. Check `JOURNAL.md` to see how the project was built step by step, and compare it with your own approach.
5. Use `EXECUTION.md` to launch, test, and iterate on the project.

## 💡 Avoiding "tutorial hell"

The most common trap in self-teaching: chaining tutorials together, understanding each step in the moment, but being unable to reproduce a similar project on your own afterward. Three rules to avoid it on this path:

- **Never copy-paste** the code from examples or answer keys: retype it.
- **Close the answer key** before attempting an exercise, even if you think you don't know how to do it.
- **Rebuild a mini-project from memory**, a few days after finishing it, without looking at your own copy.

## ✅ Key takeaways

- Short theory → immediate practice → confrontation with the solution, in that order.
- Never copy-paste the provided code: retype it and understand it.
- A project is read in order: `README` → `INSTALLATION` → your own attempt → `JOURNAL` → `EXECUTION`.
- Committing regularly with Git gives you a concrete record of your progress.
