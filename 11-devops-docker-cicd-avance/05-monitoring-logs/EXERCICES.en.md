# Exercises — 11.5 Monitoring and Log Management

## Exercise 1 — Logging with context (easy)

On the [level 07 mini-project](../../07-laravel-intermediaire/projet-mini-04-plateforme-annonces/README.en.md), add a `logger()->info()` with context (`user_id`, `annonce_id`) in `AnnonceController::store()`. Inspect `storage/logs/laravel.log`.

## Exercise 2 — Stack channel (easy)

Configure a `stack` channel combining `single` and a second `daily` channel (daily file rotation). Verify a log entry appears in both destinations.

## Exercise 3 — Filtering by level (medium)

Configure a fictional "critique" channel logging only `error` and above. Send a `debug()`, an `info()`, and an `error()`: verify only one appears in this channel.

## Exercise 4 — Custom healthcheck (medium)

Create an `/up` route (or check the one generated by default in Laravel 11+) that also tests the database connection (`DB::connection()->getPdo()`). Simulate an unreachable database (wrong credentials) and verify the healthcheck correctly fails.

## Exercise 5 — Simulating a full incident (hard)

Write a fictional post-mortem (`POSTMORTEM.md`) following the lesson's method for a made-up incident (e.g., "the queue worker silently stopped for 2 hours, notifications weren't being sent anymore"). Cover the 5 steps: notice, diagnose, contain, fix, document — with plausible technical details at each step.
